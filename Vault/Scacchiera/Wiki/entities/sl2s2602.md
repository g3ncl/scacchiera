# SL2S2602 (ICODE SLIX2)

NXP's ISO/IEC 15693 vicinity tag IC, the die inside the proposed piece transponder. Not a fitted
board part: it reaches the product inside the [[ad-circus-slix2]] converted inlay, one per piece,
32 per set.

[mpn::SL2S2602] [manufacturer::NXP Semiconductors] [category::rfid-tag-ic]
[standard::ISO/IEC 15693] [status::candidate, not yet purchased]

The immutable source is summarized in [[sl2s2602-datasheet]].

## Why this IC

ISO/IEC 15693 rather than ISO/IEC 14443-A is the decisive choice, and it follows the architecture
rather than preference:

- A vicinity card is specified to operate at roughly an order of magnitude lower field strength
  than a proximity card. The matrix couples a 18 mm tag coil to a 280 mm line antenna, which is a
  weak, badly matched coupling by construction; the protocol with the lower field requirement is
  the one that closes.
- [[bitwiseid-method]] is built on unaddressed `READ MULTIPLE BLOCKS` and `INVENTORY READ`, both
  ISO 15693 commands the SL2S2602 implements. 14443-A has no equivalent, so choosing it would
  discard the one technique that de-risks the scan-loop budget.
- [[nfc-game-board-project]], the closest working prior art, uses ICODE 15693 for exactly these
  reasons.
- [[pn5180a0hn-c3e]], already bound as the reader, supports 15693 natively and is the strongest
  15693 reader NXP ships.

SLIX2 over plain SLIX (SL2S2002): same package, same interface, 2528 bit rather than 896 bit user
memory, and NXP claims improved robustness against detuning. Detuning robustness is directly
relevant here because 32 tags sit in one field over a shared antenna. Cost difference at the
reseller is nil.

## Substitution cost

Any ISO 15693 tag with a comparable coil would work; the protocol is the binding decision, not
the die. Dropping to SLIX (SL2S2002) loses BitwiseID headroom and the detuning improvement for no
saving. Moving to 14443-A/NTAG would invalidate the scan-loop plan and raise the required field
strength, which is a matrix redesign, not a substitution.
